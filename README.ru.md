# Scriptable Variants

[English](README.md) | [Русский](README.ru.md)

`ScriptableVariants` добавляет наследование от одного родителя и переопределение отдельных полей
в данные Unity `ScriptableObject`. Данные редактируются и хранятся в компактном исходном файле
`.svariant`, который Unity импортирует как обычный `ScriptableObject` конкретного типа с уже
вычисленными итоговыми значениями.

Интеграция с инспектором рассчитана на Tri Inspector 2. Tri отвечает за отрисовку полей,
атрибуты, группы, валидацию и обработчики событий. Scriptable Variants добавляет шапку с родителем,
маркеры переопределений и действия в контекстном меню полей.

## Требования и установка

- Unity 6000.0 или новее.
- Tri Inspector 2 на коммите `f3239650e307275edd06c25e7cda1fdc7207f5b5`.
- Newtonsoft Json for Unity 3.0.2 — указан в зависимостях пакета.

Unity Package Manager не поддерживает объявление другого Git-пакета транзитивной зависимостью
Git-пакета. Сначала добавьте Tri Inspector, затем Scriptable Variants по его Git URL:

```json
{
  "dependencies": {
    "com.codewriter.triinspector": "https://github.com/codewriter-packages/Tri-Inspector.git#f3239650e307275edd06c25e7cda1fdc7207f5b5",
    "com.dcfapixels.scriptable-variants": "https://github.com/DCFApixels/ScriptableVariants.git"
  }
}
```

Для доступа к приватному репозиторию по HTTPS или SSH необходимо заранее настроить аутентификацию.

## Объявление типа варианта

`ScriptableVariant` — только базовый класс-маркер. Сериализуемые данные можно объявлять как
публичные поля или приватные поля с `[SerializeField]`. Свойства-обёртки и вызовы синхронизации
не требуются.

```csharp
using DCFApixels.ScriptableVariants;
using TriInspector;
using UnityEngine;

public sealed class WeaponConfig : ScriptableVariant
{
    [Min(0), Slider(0, 100)]
    public float Damage = 10;

    [SerializeField]
    private WeaponVisuals _visuals;

    public WeaponVisuals Visuals => _visuals;
}
```

Создайте исходный файл через **Assets → Create → Scriptable Variant...**. Найдите тип по имени,
namespace или сборке и выберите его двойным кликом, Enter или кнопкой **Create**. Имя файла вводится
прямо в Project; отмена ввода имени не создаёт исходный файл. Папка назначения показана в окне
(при выборе пакета используется `Assets`). Стрелки переключают типы, Escape закрывает окно.
Используются публичные API Unity, без кодогенерации меню и reflection-доступа к внутренним API.
Не используйте `[CreateAssetMenu]` для типов вариантов: встроенная команда Unity создаёт обычный
`.asset`, у которого нет метаданных исходного файла варианта.

## Работа в инспекторе

Для редактирования выберите файл `.svariant`. Инспектор импортёра отображает редактируемый временный
экземпляр через Tri Inspector и автоматически сохраняет изменения в исходный файл. Сгенерированный
объект для выполнения игры напрямую не редактируется. Undo/Redo восстанавливает значения и метаданные
наследования, в том числе после закрытия инспектора; отмена **Apply to Parent** восстанавливает
родителя и потомка вместе. Несколько инспекторов одного исходного файла используют общий рабочий
экземпляр. Переимпорт зависимостей обновляет рабочие экземпляры без незаписанных правок, не превращая
изменения унаследованных значений в переопределения. Если при внешнем изменении исходного файла или
родителя есть незаписанные правки, инспектор сохраняет их и сообщает о конфликте.

Ввод сохраняется с небольшой задержкой (250 мс), а также перед действиями и при закрытии инспектора.
При ошибке **Retry Save** повторяет сохранение; **Reload from Source** запрашивает подтверждение
перед сбросом правок. Неизвестные сохранённые поля блокируют обычное сохранение и остаются в файле,
пока вы явно не выберете **Remove Orphan Data...** или не восстановите их объявления в скрипте.

Назначьте в **Parent** другой `.svariant` того же конкретного типа. В шапке отображаются цепочка
наследования и меню **Actions**. Тонкая синяя полоска обозначает локальное переопределение
(`override`); более бледная полоска у составного поля означает, что переопределения есть в его
вложенных полях. Подписи и отображаемые значения переопределённых полей выделяются жирным шрифтом.

При первом назначении или смене родителя текущие значения потомка сравниваются с новым родителем.
Все различия становятся переопределениями, а существующие переопределения сохраняются. Поля
с одинаковыми значениями наследуются от нового родителя. Поля с `[VariantLocal]` всегда остаются
локальными и не получают маркеров переопределения.

Редактирование унаследованного поля создаёт переопределение. Нажмите правой кнопкой мыши на поле
или область синей полоски, чтобы выбрать **Override Property**, **Apply to Parent** или **Revert**.
Команда **Actions → Flatten** удаляет связь с родителем, сохраняя все итоговые значения.

## Формат файла и работа в игре

Корневой `.svariant` хранит значения всех полей верхнего уровня. Дочерний файл хранит только:

- GUID ассета-родителя;
- пути переопределённых полей и их значения;
- значения полей с `[VariantLocal]`.

Импортёр сначала вычисляет значения родителя, затем применяет сохранённые переопределения
и создаёт `ScriptableObject` конкретного типа в качестве основного ассета файла. Родительские
ассеты регистрируются как зависимости импорта, поэтому изменение родителя приводит к переимпорту
его потомков. Перед переимпортом используется небольшая задержка, объединяющая последовательные
изменения, чтобы ввод значений в инспекторе оставался отзывчивым.

Импортированный объект содержит готовые итоговые данные. Код игры, ссылки на ассеты и Addressables
загружают объект конкретного типа и читают его поля напрямую. В сборке игры нет графа родителей,
списка переопределений, прохода через reflection, `EnsureResolved` или API синхронизации.
Наследование существует только при импорте и редактировании исходного файла в Unity Editor.

Редакторские инструменты, которым требуется немедленное обновление, могут вызвать
`ScriptableVariantAssetUtility.EnsureResolved(asset)`. Метод запрашивает немедленный импорт цепочки
исходных файлов без `ForceUpdate` и возвращает актуальный импортированный экземпляр. Для обычного редактирования
в инспекторе и переимпорта зависимостей этот вызов не требуется.

## Особенности и ограничения сериализации

- Публичные поля и приватные поля с `[SerializeField]` определяются автоматически. Поддержка всех
  сериализуемых Unity native-типов и типов стандартных библиотек пока не гарантируется.
- Встроенные классы и структуры с `[Serializable]` поддерживают переопределение отдельных вложенных полей.
- Массивы и `List<T>` переопределяются целиком как одна коллекция.
- Значения с `[SerializeReference]` переопределяются целиком как один граф управляемых ссылок.
- `[VariantLocal]` поддерживается на корневых и обычных вложенных полях; внутри атомарной коллекции
  или значения с `[SerializeReference]` отдельные поля не имеют независимой local-семантики. Такие
  объявления теперь отклоняются с явной ошибкой: пометьте `[VariantLocal]` всю коллекцию или ссылку.
- Ссылки на Unity-ассеты сохраняются через `GlobalObjectId` и регистрируются как зависимости импорта.
  Отсутствующие, повреждённые и несовместимые ссылки вызывают ошибку, а не заменяются на null.
  Явный JSON `null` остаётся допустимой пустой ссылкой. Ссылки на сценовые и временные объекты не сохраняются.
- Для `AnimationCurve`, `Gradient` (включая цветовое пространство), `Bounds`, `Hash128`, целочисленных
  векторов и `RectOffset` предусмотрена отдельная сериализация. Native-типы без поддерживаемого
  контракта полей отклоняются, а не записываются как пустые объекты.
- `Vector2`, `Vector3`, `Vector4`, `Vector2Int`, `Vector3Int`, `Quaternion`, `Color` и `Color32` записываются
  числовыми JSON-массивами, например `[1.12, 2.01, 0.0012]` или `[3.5, 0.25, 0, 1]` (RGBA).
  Кешированные типизированные конвертеры читают и записывают компоненты напрямую, без reflection
  и временных числовых массивов. `Color` сохраняет float/HDR-значения; `Color32` — целые байты `0..255`.
  `Quaternion` хранит исходные компоненты `[x, y, z, w]` без нормализации. Массив должен содержать точное число
  компонентов; дробные или выходящие за диапазон целые значения отклоняются, а не округляются
  и не ограничиваются. Для нечисловых и бесконечных float сохраняются явные строки Json.NET:
  `"NaN"`, `"Infinity"` и `"-Infinity"`. Те же конвертеры работают внутри коллекций, `Bounds`
  и цветовых ключей градиента. Цветовой ключ имеет вид `{"color": [r, g, b, a], "time": t}`.
  Прежние объекты с именованными компонентами и плоские цветовые ключи градиента не поддерживаются.
- Пути полей, переименованных с помощью `[FormerlySerializedAs]`, обновляются при импорте.
- Старые имена полей также читаются внутри вложенных значений и элементов коллекций; при сохранении
  записываются текущие имена. Строки, похожие на даты, остаются строками, а вложенные коллекции
  заменяют начальные значения конструктора, не дополняя их дубликатами.
- Рекурсивные схемы встроенных типов отклоняются с ошибкой. Для рекурсивных графов используйте
  `[SerializeReference]`. Общие объекты и циклы сохраняются между значениями одного документа.
  Override потомка — отдельный граф: его managed-объекты не разделяют идентичность с графом родителя
  или независимо унаследованным полем. Помещайте данные, которым нужна общая идентичность, под одного атомарного владельца.
- Родитель и потомок должны иметь одинаковый конкретный тип; циклическое наследование запрещено.

Поддерживается только **formatVersion 3** — числовые массивы для векторов, кватернионов и цветов,
общий контекст managed-ссылок для всего документа. Прежние версии отклоняются; кода миграции
и чтения старых форматов нет. Демо-исходники обновлены под этот формат. Импорт не переписывает исходник.
Лимиты: 32 МиБ на файл, 128 уровней вложенности JSON и 512 ассетов в цепочке
родителей. Повторяющиеся JSON-ключи и пути значений, неизвестные поля самого документа, неверные
версии и неразрешённые `$ref` считаются ошибками.

## Безопасность сохранения и восстановление

Команды редактируют отдельные копии документов и перед записью сравнивают точное содержимое файлов,
включая цепочку родителей открытой рабочей копии. Конфликт не сбрасывает незаписанные правки.
Каждый исходный файл заменяется атомарно через временный файл с принудительным сбросом буфера на диск.
**Apply to Parent** и Undo исходников используют пакетную запись с журналом: сначала проверяются все
цели, обычная ошибка откатывает файлы и рабочие значения, импорт планируется только после завершения
записи. Это восстанавливаемая запись нескольких файлов, а не общая атомарная транзакция ОС,
охватывающая другие процессы.

Прерванные записи проверяются при старте Editor и перед следующей записью. Журналы находятся в
`Library/ScriptableVariants/Transactions`. Если внешние изменения мешают восстановлению, журнал
остаётся, а дальнейшая запись блокируется: сначала сопоставьте версии до/после операции и текущий
исходник, затем удалите уже разрешённый журнал. Не удаляйте `Library/ScriptableVariants`, пока там
есть нужные данные восстановления.

После неудачного сохранения закрытый инспектор сохраняет рабочую копию в памяти. Незаписанные
значения также резервируются в `Library/ScriptableVariants/Recovery` перед перезагрузкой сборок,
обычным выходом из Editor, после ошибок сохранения и закрытия изменённого инспектора. Повторное
открытие восстанавливает снимок, не принимая внешние изменения за его исходную версию. Нечитаемые
снимки сохраняются для ручного восстановления. Это не защита от аварии до срабатывания задержки
сохранения/резервирования. Временные ссылки, в том числе ещё не записанная ссылка рабочей копии на
саму себя, не могут надёжно резервироваться: исправьте или сохраните их до domain reload.
Обычный выход из Editor запрещается, если незаписанные правки не удалось зарезервировать.

Полиморфные JSON-типы разрешаются только среди уже загруженных типов, достижимых из объявленной
схемы данных и её сериализуемых производных типов. JSON не может запросить загрузку произвольной
сборки. Это не песочница для конструкторов и callbacks типов проекта: импортируйте только доверенные файлы.

## Интеграция с редактором и оставшиеся границы

Вложенные inline-поля тоже получают маркеры override. Маркеры и жирный шрифт обновляются по событиям
сессии и геометрии, без файлового таймера на каждом поле. Кеш исходников ограничен; проверки файлов
и отложенное сохранение общие для открытого ассета. Настоящий импорт использует готовый артефакт
родителя, а временное вычисление переиспользует результирующий объект вместо рекурсивного создания
всех предков. Большое количество потомков всё ещё требует их переимпорта; при сохранении всё ещё
создаётся снимок сохраняемого графа. Гарантий производительности для огромных графов эти изменения не дают.

У Unity-декораторов `Header`/`Space` один владелец: native-обработчик поля, если его выбирает Tri,
иначе декоратор интеграции. Приватные имена обёрток больше не используются. Для asset-only поведения
Tri на временном SO небольшой проверяемый адаптер устанавливает публичное свойство `TargetIsPersistent`
через его защищённый setter. Эта часть зависит от версии Tri; неподдерживаемая версия выдаёт ошибку.
В native ObjectField также запрещены ссылки на сценовые объекты. Сторонние custom drawers сами
отвечают за свои предположения о persistent-объекте.

Unity вызывает `OnEnable` при создании временных SO, до применения значений варианта. Не вычисляйте
там сериализуемое состояние из унаследованных значений. Покрытие native-сериализации Unity и работа
custom drawers/callbacks требуют тестов конкретного проекта; неподдерживаемые типы следует хранить
через явно описанные данные-заместители. Для этих исправлений выполнены статические/синтаксические
проверки и добавлены регрессионные тесты, но компиляция и выполнение в Unity в этой ветке ещё не проводились.

Обычные `.asset`, созданные предыдущими версиями пакета, не являются исходными файлами `.svariant`
и не участвуют в новой системе наследования. Сохраняйте резервные копии при тестировании этого
несовместимого с прежним формата в экспериментальных ветках.
