# Scriptable Variants

[English](README.md) | [Русский](README.ru.md)

`ScriptableVariants` добавляет наследование от одного родителя и переопределение отдельных полей
в данные Unity `ScriptableObject`. Данные редактируются и хранятся в компактном исходном файле
`.svariant`, который Unity импортирует как обычный `ScriptableObject` конкретного типа с уже
вычисленными итоговыми значениями.

Интеграция с инспектором рассчитана на Tri Inspector 2. Tri отвечает за отрисовку полей,
атрибуты, группы, валидацию и обработчики событий. Scriptable Variants добавляет шапку с родителем,
маркеры переопределений и действия в контекстном меню полей.

## Требования и установка

- Unity 6000.0 или новее.
- Tri Inspector 2 на коммите `f3239650e307275edd06c25e7cda1fdc7207f5b5`.
- Newtonsoft Json for Unity 3.0.2 — указан в зависимостях пакета.

Unity Package Manager не поддерживает объявление другого Git-пакета транзитивной зависимостью
Git-пакета. Сначала добавьте Tri Inspector, затем Scriptable Variants по его Git URL:

```json
{
  "dependencies": {
    "com.codewriter.triinspector": "https://github.com/codewriter-packages/Tri-Inspector.git#f3239650e307275edd06c25e7cda1fdc7207f5b5",
    "com.dcfapixels.scriptable-variants": "https://github.com/DCFApixels/ScriptableVariants.git"
  }
}
```

Для доступа к приватному репозиторию по HTTPS или SSH необходимо заранее настроить аутентификацию.

## Объявление типа варианта

`ScriptableVariant` — только базовый класс-маркер. Сериализуемые данные можно объявлять как
публичные поля или приватные поля с `[SerializeField]`. Свойства-обёртки и вызовы синхронизации
не требуются.

```csharp
using DCFApixels.ScriptableVariants;
using TriInspector;
using UnityEngine;

public sealed class WeaponConfig : ScriptableVariant
{
    [Min(0), Slider(0, 100)]
    public float Damage = 10;

    [SerializeField]
    private WeaponVisuals _visuals;

    public WeaponVisuals Visuals => _visuals;
}
```

Создайте исходный файл через **Assets → Create → Scriptable Variant...** и выберите его конкретный
тип. Не используйте `[CreateAssetMenu]` для типов вариантов: встроенная команда Unity создаёт обычный
`.asset`, у которого нет метаданных исходного файла варианта.

## Работа в инспекторе

Для редактирования выберите файл `.svariant`. Инспектор импортёра отображает редактируемый временный
экземпляр через Tri Inspector и автоматически сохраняет изменения в исходный файл. Сгенерированный
объект для выполнения игры напрямую не редактируется. Undo/Redo восстанавливает значения и метаданные
наследования, в том числе после закрытия инспектора; отмена **Apply to Parent** восстанавливает
родителя и потомка вместе. Несколько инспекторов одного исходного файла используют общий рабочий
экземпляр. Переимпорт зависимостей обновляет открытые рабочие экземпляры, не превращая изменения
унаследованных значений в переопределения.

Назначьте в **Parent** другой `.svariant` того же конкретного типа. В шапке отображаются цепочка
наследования и меню **Actions**. Тонкая синяя полоска обозначает локальное переопределение
(`override`); более бледная полоска у составного поля означает, что переопределения есть в его
вложенных полях. Подписи и отображаемые значения переопределённых полей выделяются жирным шрифтом.

При первом назначении или смене родителя текущие значения потомка сравниваются с новым родителем.
Все различия становятся переопределениями, а существующие переопределения сохраняются. Поля
с одинаковыми значениями наследуются от нового родителя. Поля с `[VariantLocal]` всегда остаются
локальными и не получают маркеров переопределения.

Редактирование унаследованного поля создаёт переопределение. Нажмите правой кнопкой мыши на поле
или область синей полоски, чтобы выбрать **Override Property**, **Apply to Parent** или **Revert**.
Команда **Actions → Flatten** удаляет связь с родителем, сохраняя все итоговые значения.

## Формат файла и работа в игре

Корневой `.svariant` хранит значения всех полей верхнего уровня. Дочерний файл хранит только:

- GUID ассета-родителя;
- пути переопределённых полей и их значения;
- значения полей с `[VariantLocal]`.

Импортёр сначала вычисляет значения родителя, затем применяет сохранённые переопределения
и создаёт `ScriptableObject` конкретного типа в качестве основного ассета файла. Родительские
ассеты регистрируются как зависимости импорта, поэтому изменение родителя приводит к переимпорту
его потомков. Перед переимпортом используется небольшая задержка, объединяющая последовательные
изменения, чтобы ввод значений в инспекторе оставался отзывчивым.

Импортированный объект содержит готовые итоговые данные. Код игры, ссылки на ассеты и Addressables
загружают объект конкретного типа и читают его поля напрямую. В сборке игры нет графа родителей,
списка переопределений, прохода через reflection, `EnsureResolved` или API синхронизации.
Наследование существует только при импорте и редактировании исходного файла в Unity Editor.

Редакторские инструменты, которым требуется немедленное обновление, могут вызвать
`ScriptableVariantAssetUtility.EnsureResolved(asset)`. Метод принудительно переимпортирует цепочку
исходных файлов и возвращает актуальный импортированный экземпляр. Для обычного редактирования
в инспекторе и переимпорта зависимостей этот вызов не требуется.

## Особенности и ограничения сериализации

- Публичные поля и приватные поля с `[SerializeField]` определяются автоматически. Поддержка всех
  сериализуемых Unity native-типов и типов стандартных библиотек пока не гарантируется.
- Встроенные классы и структуры с `[Serializable]` поддерживают переопределение отдельных вложенных полей.
- Массивы и `List<T>` переопределяются целиком как одна коллекция.
- Значения с `[SerializeReference]` переопределяются целиком как один граф управляемых ссылок.
- `[VariantLocal]` поддерживается на корневых и обычных вложенных полях; внутри атомарной коллекции
  или значения с `[SerializeReference]` отдельные поля не имеют независимой local-семантики.
- Ссылки на Unity-ассеты сохраняются через `GlobalObjectId` и регистрируются как зависимости импорта.
- Для `AnimationCurve`, `Gradient` (включая цветовое пространство) и `Bounds` предусмотрена отдельная сериализация.
- Пути полей, переименованных с помощью `[FormerlySerializedAs]`, обновляются при импорте.
- Старые имена полей также читаются внутри вложенных значений и элементов коллекций; при сохранении
  записываются текущие имена. Строки, похожие на даты, остаются строками, а вложенные коллекции
  заменяют начальные значения конструктора, не дополняя их дубликатами.
- Рекурсивные схемы встроенных типов отклоняются с ошибкой. Для рекурсивных графов используйте
  `[SerializeReference]`; общие managed-ссылки между разными сохраняемыми полями пока не сохраняют идентичность.
- Родитель и потомок должны иметь одинаковый конкретный тип; циклическое наследование запрещено.

Команды редактируют отдельную копию документа. Каждый исходный файл заменяется атомарно после
записи временного файла в той же папке. Это защищает существующий файл от частичной записи,
но **Apply to Parent** пока не является общей транзакцией для двух файлов. Обработка конфликтов
с внешними изменениями и восстановление неразрешённых ссылок также остаются ограничениями
экспериментальной ветки. Импортируйте только доверенные `.svariant`: допустимые полиморфные
JSON-типы пока не ограничены безопасным списком.

Обычные `.asset`, созданные предыдущими версиями пакета, не являются исходными файлами `.svariant`
и не участвуют в новой системе наследования. Сохраняйте резервные копии при тестировании этого
несовместимого с прежним формата в ветке `testing`.
